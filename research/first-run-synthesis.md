# First-Run Research Synthesis

Access date for sources: 2026-09-06.

## Name Check

`humanifest/humanifest` was available on GitHub before repository creation. Web search found an unrelated Portuguese festival at `humanifest.pt` and a `HUEMANIFEST` trademark application in advertising/business services. Search results did not show an existing prominent OSS project or package named exactly `humanifest`; similar package names such as `manifest`, `manifest-api`, and `agent-manifest` exist.

This is not legal clearance. Before public branding investment, perform a formal trademark search and package-index checks.

## Prior Art

The closest systems are DPGA Registry, DPG Standard, Digital Square Global Goods Guidebook, US Digital Response, UN Volunteers Online, HOT Tasking Manager, HDX, Tech To The Rescue, Catchafire, CodeTriage, Good First Issue, Gitcoin Grants, Open Collective, CHAOSS, and OpenSSF Scorecard.

Humanifest would add value only if it connects project-level humanitarian relevance to specific maintainer-confirmed issues, environment feasibility, low review burden, and evidence-labeled claims.

## Maintainer Burden

Unsolicited contributions fail when they are stale, oversized, off-roadmap, untested, CLA/DCO-incomplete, AI-generated without human ownership, or duplicative. Humanifest therefore treats maintainer confirmation as a hard gate rather than a courtesy.

## Adversarial Findings

The strongest objections are contribution spam, Goodharted rankings, false expertise, provenance risk, maintainer burden, and becoming a meta-project. Design responses are hard gates, parked states, evidence labels, anti-spam rules, no autonomous outreach, and no implementation before maintainer confirmation.
